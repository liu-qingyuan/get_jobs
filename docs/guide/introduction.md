::: warning 本机程序与静态文档站不同
这里是免费 GitHub Pages 说明站，不托管工作台，也不连接账号或本机资料库。实际程序须在已确认版本的本机显式启动；启动管理页不自动打开招聘浏览器、调用 AI 或申请岗位。
:::

## 项目概述

**Get Jobs** 在保留原国内平台入口的基础上，提供本机资料、独立简历、求职范围、候选、匹配、材料准备与回执管理。官网、OfferToday、Boss、JobsDB 接入统一链路，但**不等于四渠道都能自动发送**。

先看 [多平台能力总览](/platforms)：它分别列出代码接入、隔离验证、实站读取、外发资格及原国内入口的维护差异。官网需要配置可信执行器；OfferToday 公开找岗已实站通过，但自动发送两版均未验收、保持关闭；Boss 与 JobsDB 的受控外发尚未完整实现，不是仅欠测试。

## 当前技术结构

两张可见的当前 C4 图：[系统上下文](/architecture/c4-context) · [容器与运行结构](/architecture/c4-containers)。图源与静态图一并维护；旧三层示意不再作为现状图。

管理界面使用 **Next.js / React**；本机主程序使用 **Java 21 / Spring Boot / SQLite**。Boss 只读接入复用 Java / Playwright，OfferToday 与 JobsDB 使用独立 Python / Node.js Adapter，官网及材料处理依赖明确配置的可信本机命令。资料、附件与任务记录保留在本机，各渠道会话不混用。

资料、范围预算、候选匹配、备料、执行回执及项目验证是现有主程序内的职责，不是新增的云端微服务。可信命令不是 OS 沙箱；界面、模型或配置存在都不能证明真实平台已验收。

## 已有能力与边界

- **事实与材料**：确认资料来源和适用性；港区 / 国内、中 / 英文及岗位简历独立维护，不自动同步翻译或捏造经历。所选核准字节和版本绑定材料，AI 整理不是事实确认。
- **范围与候选**：一次范围限定来源、地区、材料、动作、累计预算与到期时间，默认仅准备；只读候选保留来源、身份、取得时间及完整 JD，例外不隐藏。
- **匹配与备料**：理由保留 JD 和材料依据，相关变化才重评；可证实的原字节复用或事实原值重排可核准，开放改写仍是草稿，不把分数当真实性证明。
- **执行与回执**：平台能力、有效范围、材料和阶段 claim 分别成立才可外发；UNKNOWN 不重投，退出码 0 不是送达或正式申请证明。原逐岗人工入口保留原有语义。
- **项目与独立验收**：有依据的缺口可形成独立项目；执行、独立验收及有限成果回流分别授权，不改写旧简历 / 申请历史，不冒充商业经验或年限。
- **状态提醒**：页面运行时更新状态，用户许可后尽力提供桌面通知；不承诺手机、全天候或原 Webhook 的真实送达，见 [AI 与通知](/guide/ai-and-push)。
