# ⚙️ 核心与平台配置详解

本地审核版使用 Web 面板保存筛选和资料配置。保存、上传或开关都不等于发送授权；源码同步与模拟测试不代表真实平台已验收。详见 [本版同步与限制](/upstream-sync-36bf5f9) 和 [工作台使用](/workbench)。

新库默认只扫描（`debugger=1`），AI/图片/重复发送关闭，不预填个人经历或黑名单。

---

## 1. 基础全局配置

在控制面板的“系统设置”或配置文件中，你可以定义以下全局投递策略：

| 配置项 | 说明与建议值 |
| :--- | :--- |
| **目标城市** | 支持多选（如：北京、上海、杭州、深圳、广州等） |
| **岗位搜索关键词** | 例如：`Java`、`前端`、`大模型算法`、`全栈开发` |
| **期望薪资区间** | 例如：`15-25k`，程序会自动过滤低于该区间的职位 |
| **经验与学历要求** | 过滤不符合个人履历的硬性门槛（如硕士限定、5年以上等） |
| **每日投递目标数** | 建议控制在各平台官方安全限制阈值内 |

## 2. 各招聘平台专属配置

### 🟢 Boss直聘配置

#### 向已沟通 Boss 再次发送消息

上游的配置字段和消息存储保留，但本审核版的重复发送开关锁定，不能开启发送。旧库的启用值仍如实显示，不自动覆写；可点击明确的关闭按钮再保存，已存跟进消息不删除。

数据库升级补列默认关闭并保留已有设置。开启旧值不会产生授权：执行会在访问浏览器/模型之前拒绝重复发送。首次联系仍需精确、有效、单次的岗位审核记录。

<p align="center">
  <img src="/images/boss配置.png" alt="Boss配置" style="max-width: 90%; border-radius: 8px; border: 1px solid var(--vp-c-divider);" />
</p>

- **打招呼限额**：以当前平台与账号实际提示为准；不按历史固定次数自动海投。
- **自定义打招呼语**：
  - 若开启 AI 打招呼模式，系统将动态调用模型结合你的简历和 JD 生成；
  - 若未开启 AI，请务必在配置项中预留默认打招呼语文本，否则可能导致投递中断。
- **图片简历（`sendImgResume`）**：
  - 仅保留运行时上传、替换和预览，不自动发送。不要将个人简历放入资源目录；本版会排除旧资源简历打包。
  - 设为 `true` 会被单岗正文审核门禁拒绝。旧开启值可明确关闭后保存，文件不被删除；上传不是附件审核。
- **黑名单自学习机制**：
  - 系统在遍历沟通记录时，如果检测到 HR 回复“不合适”、“已招满”等关键词，会自动将该企业记录至黑名单中，未来绝不重复打扰。

## 3. Cookie 管理与扫码登录

Get Jobs 使用扫码登录与本地登录态管理。具体登录方式以平台页面为准，猎聘与智联按 README 要求使用绑定微信的账号：

1. **明确打开**：管理启动不打开招聘浏览器。Boss 页点击“打开 Boss 登录浏览器”并确认后，才调用本项目登录入口；不自动填写账号/验证码，不开始投递。
2. **手机扫码**：在弹出的浏览器中，使用手机端对应 App 扫码确认。
3. **安全持久化**：登录成功后，程序在本机保存登录状态。请妥善保护本地 Cookie、浏览器数据与数据库，不要上传或分享这些文件。
4. **核验状态**：有效期以平台为准。保存配置或 Cookie 请求返回并不代替网站登录核验；失效时由用户重新登录。
