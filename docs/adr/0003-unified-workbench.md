# ADR 0003：统一管理，不合并简历文案或浏览器会话

## 决策

用户已授权统一工作台 V1（issue #4）。接续 ADR 0001/0002：在 JobsDB 副本加入 Spring/Next.js 管理入口，允许明确启动管理进程，但默认禁用招聘浏览器自动启动。原 `get_jobs/` 的文件、进程、数据库和浏览器不修改；现有国内安全修复仅复制源代码。旧 JobsDB CLI、数据目录、锁、审核和 UNKNOWN 防重合同保留。

个人资料由本地 Workbench Module 拥有，包含确认状态、来源、地区/网站作用域。旧资料仅显式预览导入，导入后仍未确认；更新联系方式不覆盖历史回执。密码、Cookie、验证码不导入通用资料。港区/国内、中/英文简历是四类独立档案，岗位版另存；批准后以附件 SHA256 和资料快照绑定任务，不就地覆盖。

官网不按公司实现驱动，也不自建浏览器 Agent。由操作人配置一个现有可信本机 CLI，参数数组直接启动，不拼接 shell。一次只启动一个执行任务（官网 AI、OfferToday 脚本和只读读取共享运行槽）；任务包和日志只保存在忽略的私有目录。任务凭据只用于该任务事件，提交占位必须收到 HTTP 成功响应后才可点击提交。执行器是受信任本机程序，不是操作系统沙箱；网页内容不得成为额外指令，禁止读取任务无关资料。仅向执行器交付已批准且适用的资料，而非全库。

工作台只记录执行器/用户报告及其证据，不声称直接观察了浏览器或雇主决策。退出码 0 不是成功；缺回执保留 UNKNOWN。平台申请仍使用原页面/CLI，不能把一个工作台岗位批准扩大成原有批次授权。JobsDB 账本只读展示并参与重复检查。

## 取舍

复用 Java 21、Spring、SQLite 与现有 Next.js，避免新框架。工作台数据单独保存在 `.workbench/`，与平台登录态隔离。企业状态先主动检查后登记，通知仅在工作台页面运行时尽力提供；不新增全天候调度、远程消息系统或自动项目执行。

## OfferToday 的单岗脚本接入

用户明确要求 OfferToday 使用已打开并登录的 Chrome。此渠道通过官方扩展的已授权标签页组复用现有浏览器，不新建登录 profile、不复制 Cookie，也不让它共享 Boss/JobsDB 的会话文件。平台网页知识由独立脚本 Adapter 拥有，工作台沿用材料冻结、单次执行及 UNKNOWN 合同，不另建浏览器 Agent。

OfferToday 只允许 HK 单岗 APPLICATION，可由 HTTP 在用户批准后显式启动附带脚本，这是单岗执行而非批次授权。官网仍走原外部命令；脚本读取当前已加载职位不创建或批准申请。首次消息与附件分开留证，只有匹配同岗、同次、同会话和冻结附件哈希的简历送达回执才完成。网页控件或自动招呼无法核实时停止，不借用官网 AI 猜测发送。

实站只读核对表明，职位卡片的 Chat/Apply 在打开编辑器前就调用状态变更接口，不能用作无副作用预检。适配器改用已登录页面的原生聊天状态入口，绑定详情返回的岗位与招聘者，再通过真实文字编辑器和简历选择器执行。原生 store/接口依赖被封装在 Adapter 内并固定已验证客户端版本；站点更新时阻塞，不尝试其他 minified 导出或猜测新流程。

消息清空、DOM 新行、transport packetsend 或本地 Loading 都不是送达证明。文字与简历必须分别对应新的、同一招聘者会话中的平台历史记录；简历还绑定审核文件的实际字节哈希与站内附件 ID。站内旧附件不能仅凭文件名或默认选中复用。新增附件不能删除/替换用户其他附件或改默认简历，已知容量/审核/字节校验阻塞应在联系前发现。

OfferToday 的 SUBMITTED 表示本次核准简历已获得上述平台持久化回执，不等同于招聘者已读、雇主决定或平台「求職紀錄」状态已更新。工作台只校验和保存受信执行器/人工提交的证据，不独立向招聘平台背书。

## AI 优先事实基线（issue #9，父 spec #7）

V1 的逐条录入保留作澄清/兜底，不再是唯一的事实核对入口。材料事实 Module 接受明确上传的文本、已登记来源 ID 和独立简历 ID；不接受服务器路径，不扫描目录，也不默认读取旧 JobsDB 或运行库。复用现有可信命令、私有任务包、有界超时和独占运行槽，不另造模型框架。材料分析使用单独的 `MATERIAL_REVIEW` 数据合同，无申请回调 token、账号或浏览器权限；可信执行器仍非 OS 沙箱。

模型只能提交候选与缺失说明。Module 按选定来源逐字核验依据、固定作用域，并展示重复/冲突；凭据和可识别指令行隔离，模型提供的确认标志及额外路径不生效。只有用户集中选择的可核对项成为确认事实；不把模型表述当作独立真实性证明。变化的来源保留版本，失去旧原文依据的当前事实退回待核实；原文依据未变时复用原确认，不要求每轮重填。事实修改/删除保留确认版本与来源，已批准任务的历史快照不回写。

简历仍是四类和岗位版的独立不可变记录，核准绑定实际附件 SHA256 与正文 SHA256。PDF/DOCX 无配套可读正文时明确缺证据，不猜测内容或自动核准。后续准备通过带适用地区、语言和可选网站的只读基线 Interface 获取当前已确认事实及匹配的核准简历；不获取未确认候选或其他地区/语言附件。范围授权、自动找岗、外发与项目执行不属于 #9，也不因确认基线而授权。

## 有界范围策略（issue #10，父 spec #7）

V1「仅逐岗人工批准」不再是唯一的授权来源，但其旧记录与执行入口语义保留。新增范围策略 Module 集中拥有一次范围确认、累计计量、冻结动作授权与失效判断；不把策略来源标成用户逐岗审批，也不在本票自动批准任务或启动 Runner。材料事实 Module 仍拥有所选事实/独立简历版本及适用性，不由模型扩大所选集合。

采用单个当前范围的追加版本历史与同库存储事务，不新建调度或独立预算框架。预检只读、冻结授权不占量，消费时以 `BEGIN IMMEDIATE` 统一复核范围、所选材料、单目标与预算并计入所授资源上限；重启及新版本不重置已耗量。消费者必须在每个不可逆阶段前消费独立授权、执行实际资源上限并取得原 claim，不能拿成功的旧响应当作重试许可。权限检查与预算写入不能散落在后续渠道/编排中各自实现。

暂停/恢复也追加版本，防止暂停前的授权在恢复时复活。事实变化、所选附件字节不符、到期、撤销及预算不足均拒绝消费。已消费动作只允许追加一次结果，迟到证据不回滚；外发目标持续参与防重。首次联系与附件是两个授权/计量阶段，附件需要同版本、同目标和所选简历的联系证据；撤销或版本变化后不继续旧阶段。策略记录是可信消费者的报告，不代替原执行回执或雇主观察。项目执行/成果入库没有可借用的权限，留给对应 Tickets 的资源合同。

## 默认只读候选（issue #11，父 spec #7）

默认主屏从手工建任务切换为持久候选队列；旧任务/账本与人工授权语义保留。候选 Module 拥有来源、身份、完整性及读取断点，不产生申请任务或借用申请回调。官网沿用通用可信命令，OfferToday 在独立只读操作中读取已加载列表和原生公开详情，绝不复用会打开聊天/附件选择器的 preflight。未知版本或详情 schema 明确受限，不猜测站点内部导出或翻页接口；实站只读样本验收不包含在开发授权内。

每页含必要详情，由范围策略事务预扣整页候选槽、秒数和官网模型上限，OfferToday 零模型；失败、重复或不足不退款。Runner 复用独占槽和有界进程时限，可信官网命令负责执行所授 token/来源上限，仍不是 OS/模型沙箱。列表授权暂不应用选择词（列表本身尚无 JD），每个返回岗位按实际标题/全文/来源核验，拒绝候选不能进入后续匹配。续读按当前范围重核固定来源，重启/新范围不清零计量。

候选身份只去除已列明的推广字段，保留未知查询身份；旧申请防重继续采用原有更保守的规则，避免本票静默放宽 UNKNOWN 重投保护。进度页保存游标及例外，中断后只恢复只读检查点，不自动启动浏览器或外发。

## 有依据的批量匹配（issue #12，父 spec #7）

匹配 Module 拥有分析身份、来源引用、逐候选例外和持久缓存，不拥有事实确认或授权。HTTP 显式启动最多 20 岗后，候选/状态读取可对该批的相关变化自动重评；同输入和失败均命中缓存，无额外模型调用。缓存键包含完整 JD 与岗位条件、当前范围版本/有效性、仅适用已选事实/材料及匹配规则版本，不含无关地区/语言或网站内容。引用逐字核对并留存源快照，不宣称程序能独立证明模型语义质量。

为满足核实后自动重评，新增**匹配消费者专用的只读预算预扣**：只重读原范围 factIds 的当前已确认内容，冲突/未确认值不出包；简历仍须原先选定、核准、适用且字节可核验。这个读取不续签原 #10 冻结授权：通用 authorize/consume、准备和外发仍按原材料快照拒绝变化，不自动新增事实 ID 或材料。待核实项仅有已选事实标识/标签和原因，模型不能据此确认旧值。

复用通用命令和独占槽，服务器预扣每个未命中岗位的秒数/token 上限，批次硬截止不超过其中任一秒数额度，可信命令负责总 token 上限；失败不退款，输出异常不自动重试。启动前保存中断例外，重启不靠轮询重复模型。完整 JD 哈希、JD 原文、适用事实/材料原文引用和允许字段均由服务器核验；支持、硬性不足或真实经验缺口不能没有事实/材料依据，未知证据只能待核实。逐岗输出例外不影响同批合法结果；整个命令失败则该批逐岗显示例外。缺口读取只返回当前有效的有依据建议，不执行项目、不生成外发文件。

## 可证实材料与策略核准（issue #13，父 spec #7）

V1 逐岗人工审批历史保留，新单岗材料包明确标注 `SCOPE_POLICY`，不向旧任务写伪造的人审事件、不 claim 或发送。本票沿用发布局部八图的逻辑职责；准备 Module 拥有变换证明、独立版本和冻结包，范围策略 Module 仍拥有有效性、动作许可、累计预算和防重。后续渠道只消费这份统一合同，不复制材料核准策略。

不引入声称能证明任意 AI 改写的 verifier。窄路径先通过对抗样本：有效来源 ID、模型 `verifier=true` 或 `approved=true` 均不足以支持新数字、商业经历、年限或结论。`ORIGINAL` 只复用已核准且正文与实际字节一致的文本/规范 DOCX；`REORDER` 只选取/排序适用已确认事实的完整原值，以固定渲染生成独立岗位 DOCX，不覆盖四类基线。任意 PDF/Office 文件不能仅凭配套正文自动核准，仍为例外；`REPHRASE` 或不精确相等的正文/消息保留草稿。这是有意限制自动核准的能力，而非通用语义证明或真实推荐质量验收。

OfferToday 在一次范围确认中显式选定已确认的邮箱/电话字段及可识别完整值，再核对实际资料/偏好（字段/格式检查不冒充实际平台资料验证，普通经历不能充当联系方式），冻结适用联系方式、无经历主张的精确固定消息及其哈希；最终附件仍须可核验 PDF/DOCX，本窄路径生成 DOCX。旧逐岗联系方式核对不自动转成范围核对。每岗核准包保留所选基线 ID 与冻结独立文件 ID（可能不同）；动作前统一重核当前范围/匹配/事实、实际字节及 UNKNOWN/重复目标，但不创建授权、扣除外发量或获得 claim。后续执行仍须消费本阶段授权并把冻结包的实际文件交给单岗执行 Module，不得将范围许可或核验响应当作送达/重试许可。

复用现有可信批量命令和独占 Runner；每个未命中岗位预扣完整备料秒数/token，上限失败不退款。相同输入含失败跨重启复用；事实变化不自动续签备料授权。准备结果、草稿/例外、材料正文/哈希、版本与依据在默认候选主屏可见。

## 连续求职周期与阶段 claim（issue #14，父 spec #7）

更新 V1 默认逐岗人工推进决策：用户一次启动有界求职周期，编排 Module 在同一独占槽内自动完成发现、匹配、备料与官网/OfferToday 逐岗执行。独立阶段入口只作高级兜底，旧人工任务、人审事件、UNKNOWN 和平台账本语义不改写；策略任务不能转经旧 approve 冒充人审。沿用本票发布八图的逻辑职责，具体编排由 WorkbenchWorkflow 拥有，不另造调度/浏览器框架。

同库存储事务把每阶段的范围/材料/目标重核、预算消费和 task claim 绑定。已预扣完整执行秒数及官网模型上限（可信 CLI 执行 token 限额，非沙箱），CONTACT/APPLY/SEND_CV 分别扣一次外发；失败不退款。OfferToday 联系回执先入库，附件前再次 claim；暂停、变更、到期、材料变化和预算耗尽后不开始新阶段，已有联系与 UNKNOWN 不回滚。对应 CV 回执仍须新消息、同会话及冻结实际字节绑定。

持久轮次保存来源游标、候选/材料/单岗引用及必要例外。显式恢复仅重核已知未外发候选；UNKNOWN/SUBMITTED 不重投，其他合格岗位可继续。完整阶段缓存复用，范围/材料变化不自动续签。资源槽直到主命令及后代确实释放才交给下一个岗位；内置 Python 标准库的 POSIX 私有进程组监护保持组长存活至清理，排除短命 launcher 退出后后代失联的漏洞，以 release proof 而非主 PID 消失确认资源释放。自有监护进程 PID/启动时间租约用于中断后释放；身份不明或无释放凭据时阻塞，不终止其他进程或强杀监护后假定成功。重启使所有旧执行凭据失效、不自动外发；策略任务没有成功 claim 时能证明未获发送许可，区别于旧任务的保守 UNKNOWN。

这些是开发技术链路，不是实站推荐质量/真实送达验收；测试只用临时数据和 fake 来源、模型、执行器，最终运行版本切换仍由 #19 收口。

## Boss 只读接入与待核实能力（issue #15 的完整增量，父 spec #7）

复用现有 `PlaywrightManager` 的拥有线程及 Boss 列表/详情身份知识，不另建浏览器框架、进程命令或会话目录。只读 Adapter 只在本副本已显式登录且原 Boss 任务空闲时使用新建的自有标签页，不调用 `ensureReady`，不读取旧审核 JSON、原目录、账号库或迁移 Cookie。工作台独占槽与浏览器拥有线程串行，旧任务进行中拒绝读取。当前已加载列表规范去重，分页只遍历这份列表并绑定其指纹；不滚动、猜测翻页或未知详情接口。只从导航过程中实际观察到的 GET 详情响应取正文，复用 `zpData.jobInfo.encryptId/jobName/postDescription` 与 `brandComInfo.brandName` 合同；目标/schema 不匹配、访问受限或无响应保持信息不足，不把看似完整的 DOM 文本当身份证明。自有页的网络守卫仅放行列表/详情、已知只读接口与静态资源 GET，其他请求拒绝；关闭自有页，不接管用户页面。

窄核对否定了「旧联系方法可以直接消费机器精确文本授权」这一假设：`Boss.resumeSubmission` 必须先点「立即沟通」，点击后才知道平台是否已自动招呼。该分支的「已向BOSS发送消息」只证明 DOM 联系结果，不绑定审核正文。即使后来出现编辑器，也不能倒推之前没有自动发送；更不能用联系证明附件或在线资料送达。因此不提取一个表面受控但已在预检外发的 wrapper。范围策略明确拒绝 Boss 的 CONTACT/APPLY/SEND_CV（`CAPABILITY_UNVERIFIED`），无核准授权/消费/claim/发送任务，不能借官网任务或状态查询绕过；图片、重复联系与未知开关也不能扩大能力。生产能力声明不是 fixture 属性或配置开关。

统一候选、匹配和可证实材料包可用；Boss 草拟消息不声称有附件随附，准备与执行能力分别展示。原人工 Boss 单岗合同、DOM 和配置不改写。**精确单岗外发验收仍未完成，#15 保持 open、待能力核实**：需另获授权的真实只读核对或用户有权提供的脱敏回放，证明不可逆动作前可绑定精确正文及其真实回执；核实不包含实发、上传或试投。本增量不承诺平台发送接通，也不切换正在运行的可见版本。

## JobsDB 只读接入与待核实外发（issue #16 的完整增量，父 spec #7）

在原 Python CLI 增加独立 `read-candidates taskFile --data-dir ...`，复用当前副本的独立会话和 `run.lock`，不启动原 apply/batch、不载入全局资料或 answers、不新建登录 profile，不读写原申请账本。Runner 使用配置确定的数据目录和参数前缀，页面预算先由策略扣除，零模型脚本受同一独占进程槽和硬时限约束。候选规范身份、统一匹配/独立材料及原账本防重继续复用现有 Module，不另造浏览器或渠道调度框架。

只读网络守卫通过 pinned Scrapling 的公开 `page_setup` 在导航前安装到整个 BrowserContext（含 popup 首次请求）：只放行受支持列表/数字详情导航和窄范围静态资源 GET，拒绝 XHR/fetch、其他方法、其他来源及 apply 路径；禁用此操作的 CF solver，不通过安全挑战或登录来扩大读取能力。只读 Browser 创建时阻止新 Service Worker 注册；持久 profile 只要存在 Service Worker 存储目录即在启动 Chrome 前保守拒绝，因原有 worker 可绕过路由，不能仅靠 block 选项。原会话和 worker 状态不删除、不迁移；该拒绝可能包含无活跃 worker 的目录，仍显式停在读取例外。现有交互式 CLI 的 CF、Profile、页面清理、锁、逐岗确认与 UNKNOWN 合同不变。只遍历有界的当前已加载列表，续读绑定其身份指纹，不猜测远端翻页；缺标题/公司 schema、错岗、缺全文或预算不足都不伪装完整覆盖。真实 DOM/schema、来源代表性和读取质量仍须另获授权核对。

拒绝把 `Flow.prepare_automatic()` 包装成“已受控单岗申请”：原流程的 Profile 会随申请发送，尚无证据证明只包含本次适用事实；review 的附件文件名不证明冻结字节，积极文案也未绑定本次材料。原批次许可和固定答案不能补足这份合同。因此范围预检/核准显式返回 JobsDB `CAPABILITY_UNVERIFIED`，不产生外发授权、claim 或发送任务，不借用官网状态查询或其他渠道；材料包和一次联系方式核对不解除该限制。原人工 CLI 与历史记录保留，不声称本票已完成其精确单岗目标。
