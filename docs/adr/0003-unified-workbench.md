# ADR 0003：统一管理，不合并简历文案或浏览器会话

## 决策

用户已授权统一工作台 V1（issue #4）。接续 ADR 0001/0002：在 JobsDB 副本加入 Spring/Next.js 管理入口，允许明确启动管理进程，但默认禁用招聘浏览器自动启动。原 `get_jobs/` 的文件、进程、数据库和浏览器不修改；现有国内安全修复仅复制源代码。旧 JobsDB CLI、数据目录、锁、审核和 UNKNOWN 防重合同保留。

个人资料由本地 Workbench Module 拥有，包含确认状态、来源、地区/网站作用域。旧资料仅显式预览导入，导入后仍未确认；更新联系方式不覆盖历史回执。密码、Cookie、验证码不导入通用资料。港区/国内、中/英文简历是四类独立档案，岗位版另存；批准后以附件 SHA256 和资料快照绑定任务，不就地覆盖。

官网不按公司实现驱动，也不自建浏览器 Agent。由操作人配置一个现有可信本机 CLI，参数数组直接启动，不拼接 shell。一次只启动一个 AI 任务；任务包和日志只保存在忽略的私有目录。任务凭据只用于该任务事件，提交占位必须收到 HTTP 成功响应后才可点击提交。执行器是受信任本机程序，不是操作系统沙箱；网页内容不得成为额外指令，禁止读取任务无关资料。仅向执行器交付已批准且适用的资料，而非全库。

工作台只记录执行器/用户报告及其证据，不声称直接观察了浏览器或雇主决策。退出码 0 不是成功；缺回执保留 UNKNOWN。平台申请仍使用原页面/CLI，不能把一个工作台岗位批准扩大成原有批次授权。JobsDB 账本只读展示并参与重复检查。

## 取舍

复用 Java 21、Spring、SQLite 与现有 Next.js，避免新框架。工作台数据单独保存在 `.workbench/`，与平台登录态隔离。企业状态先主动检查后登记，通知仅在工作台页面运行时尽力提供；不新增全天候调度、远程消息系统或自动项目执行。

## 验证

临时 SQLite、fake 外部进程与 localhost 回调验证材料冻结、作用域、独占启动、提交占位和回执。浏览器页面测试只使用本机假资料；真实账号/官网实投必须单独授权验收。
