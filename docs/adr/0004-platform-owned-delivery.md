# ADR 0004 平台执行外部动作并负责防重

2026-11-28 · 部分取代 [ADR 0003](0003-unified-workbench.md) 的工作台编排与 JobsDB 单岗 claim 顺序。

工作台拥有范围、累计预算、材料核准、执行凭据与证据展示。准备包交付适用且获准对外使用的事实、简历原字节和 SHA256，以及该动作需要的精确核准正文。目标、动作授权与 attempt 独立绑定。每个平台沿用既有入口执行外部动作，在自己的原生账本防重并解释回执。

JobsDB 的工作台和持有效授权的 CLI 共用 Python `apply-single`。在同岗现场 JD、范围、所选字节及授权有效时，首次上传前工作台事务消费一单位 outbound 并记录可能已披露。工作台凭据失效、进程中断或上传后的核验失败均保留这笔消费和 UNKNOWN。完整问卷、批准答案及 review 页独立观测的选中简历 ID 与本次上传 ID 均吻合后，Python 才以同一 SQLite 事务写入岗位唯一 UNKNOWN 占位与 attempt 来源。最终复核后至多提交一次。Java 发送版本化任务文件，从版本化结果文件及 Python 只读历史查询取得证据。原生历史行继续参与防重。Runner 沿用单线程执行和进程租约，CLI 用 profile 锁串行执行。超时、中断或缺少绑定回执时保留不确定性。

申请受理、CV 实际送达与原生占位分别记录。JobsDB 消息为 `not applicable`。披露前停止时 CV 为 `not attempted`。披露后只有与本岗、本次提交及核准附件相连的实收附件证据才能确认 CV，其余为 `unknown`。

逐渠道切换。该渠道通过双入口先后和并发防重、同地址 JD 变化、披露或 claim 后中断及重启禁止重投验证后，才撤下平行执行路径。回滚只切回该渠道的已知入口，保留原占位、回执和已耗预算，历史 attempt 永不重放。其余渠道各自验收。
